# Gutenberg Theme

A modular WordPress theme built on custom Gutenberg blocks (ACF PRO + `block.json`).

## Requirements

- WordPress 6.x
- PHP 7.4+
- Node.js 18+ / npm — build tooling only, not needed in production.

## Setup

```bash
npm install
npm run build
```

This produces `main.css`/`main.js` and each block's CSS/JS in `assets/dist/`, which `inc/assets.php` enqueues.

## Development commands

| Command | What it does |
|---|---|
| `npm run dev` | Development build + watch (rebuilds on file changes) |
| `npm run serve` | One-off development build (no watch) |
| `npm run build` | Production build (minified, no sourcemaps) |
| `npm run make:block -- <block-name>` | Scaffolds a new block (see below) |
| `npm run lint:css` | Lint SCSS with stylelint |
| `npm run lint:css:fix` | Auto-fix SCSS style issues |

`npm run dev` also starts BrowserSync (proxying `http://localhost:10044` — your Local site's port; change it in `webpack.config.js` if needed).

## Theme structure

```
blocks/                 — custom Gutenberg blocks (each block is its own folder)
  container/
    block.json           — block metadata, style/script paths
    render.php            — server-side render (ACF render template)
    style.scss            — block styles (compiled to assets/dist/blocks/<name>/style.css)
    script.js              — block JS, if needed (optional, not created by default)

assets/
  src/global/            — theme-wide styles/scripts (main.scss, main.js)
  dist/                  — compiled output (git-ignored, generated by the build)

inc/                     — PHP modules, loaded from functions.php
  setup.php               — theme supports, menus, textdomain
  assets.php              — enqueues main.css/main.js
  blocks.php              — auto-registers every block in /blocks
  cleanup.php             — <head> cleanup, disables emoji/comment feeds, etc.
  helpers.php             — template helper functions (show_template, acf_link, ...)
  woocommerce.php         — WooCommerce customization hooks (commented out by default)
  acf-placeholder.php     — get_field()/the_field() stubs in case ACF is disabled

parts/                   — reusable template chunks (get_template_part)
acf-json/                — exported ACF field groups (auto-synced)
theme.json               — color palette, typography and layout sizes for the block editor
bin/                      — tooling scripts (block generator)
```

## Creating a new block

Webpack auto-discovers blocks — you don't need to touch the build config.

1. Scaffold the block:

   ```bash
   npm run make:block -- hero-banner
   ```

   This creates `blocks/hero-banner/` with `block.json`, `render.php` and `style.scss`, already filled in with the block's name and title.

2. If the block needs JS (e.g. to initialize a slider), add `blocks/hero-banner/script.js`. Webpack will pick it up on the next build and compile it to `assets/dist/blocks/hero-banner/script.js`. Add `"script"` (loads on both front end and editor) or, preferably, `"viewScript"` (front end only) to `block.json`.

3. If the block needs custom fields, create a field group under **Custom Fields**, and attach it to the block with a `Block is equal to theme/hero-banner` location rule. ACF automatically saves the JSON to `acf-json/` (already wired up in `inc/setup.php`).

4. Rebuild the assets (`npm run dev` while developing, `npm run build` before deploying).

### Using libraries inside a block (Swiper, GSAP, etc.)

Import the library **inside that block's own `script.js`**, not in the shared `assets/src/global/main.js` — this way it only ships in that block's bundle and only loads on pages where the block is actually used:

```js
// blocks/slider/script.js
import Swiper from 'swiper';

document.querySelectorAll('.slider-block .swiper').forEach((el) => {
    new Swiper(el, { loop: true });
});
```

For the library's CSS (e.g. `swiper/css`), import it from that same block's `style.scss` so it ends up in the `style.css` already declared in `block.json`.

## theme.json

The color palette, typography scale (`fontSizes`) and layout widths (`contentSize`/`wideSize`) live in `theme.json` and are exposed to the block editor (color picker, font size dropdown, etc.). These values are kept in sync with `assets/src/global/base/_variables.scss` — update both places when changing brand colors or font sizes.

## Code style

- `.editorconfig` — indentation rules (tabs for PHP/SCSS, spaces for JS/JSON), picked up automatically by most IDEs.
- **stylelint** (`stylelint-config-standard-scss`) — `npm run lint:css`.
- **PHPCS** (WordPress Coding Standards) — requires Composer:

  ```bash
  composer install
  composer lint       # check
  composer lint:fix    # auto-fix (phpcbf)
  ```

  If Composer/PHP aren't available locally (e.g. in an isolated environment like Local), run these from your local server's Site Shell instead.
